# Приёмка раскладки Sankey

Проверяем геометрию отрисованного графика при масштабе 100%, с реальной толщиной линий. Для обратных связей «полка» — горизонтальный участок обхода, «нога» — его вертикальный участок. Группа — связи к одному узлу, которые идут по одной стороне и делят общий коридор. Одноимённые подписи могут относиться к разным узлам и разным коридорам.

| Критерий | Что проверять |
| --- | --- |
| Связь видна целиком | Путь соединяет назначенные порты. Линия с учётом её толщины, узлы и подписи помещаются в область SVG. Проверяем самые верхние и нижние петли, а также отображение при наведении. |
| Маршрут читается непрерывно | Прямые и дуги стыкуются по касательной, без перегибов и захода в чужие узлы. Широкая дуга сохраняет читаемую внутреннюю кромку. |
| Группа остаётся группой | Полки и ноги занимают соседние места в общем коридоре. Между ними нет чужой связи, если её можно провести снаружи. Согласуем порядок ног, полок и поворотов там, где порядок портов допускает вложение. |
| Зазор ровный и минимально достаточный | Меряем между видимыми кромками на общей длине параллельных участков. Цель — настроенный зазор `circularGap` (1 SVG px в контрольных RT и OW, 5 SVG px по умолчанию в библиотеке). Для соседей без препятствий предлагаем допуск от `gap − 0,25` до `gap + 1` px. Зазор больше этого требует указать препятствие. Отрицательный зазор на общей длине — дефект. У портов, где линии примыкают к одному узлу, зазор естественно сходится к нулю. |
| Внешняя петля огибает внутреннюю | Если порты и свободный коридор допускают вложение, внешний маршрут проходит за всей внутренней петлёй вместе с её обводкой. Поперечное пересечение допустимо, когда исключить его при заданных позициях и порядке портов не удаётся. Для спорного случая фиксируем пару путей и ограничение. |
| Обход занимает только нужное место | При возможности приближаем ноги и полку к соседям до настроенного зазора. Дополнительную глубину обосновываем вложенными петлями, узлами или минимальными радиусами поворотов. |

Перед приёмкой запускаем `npm test` и открываем контрольные диаграммы целиком. Синтетические тесты в `test/circular-corridor-packing.test.js` проверяют порядок семей и зазоры, `test/right-turn-compaction.test.js` проверяет, когда можно сдвигать правую ногу, `test/circular-corridor-compaction.test.js` проверяет сближение соседних полок и ног разных групп, а `test/chart-viewport.test.js` проверяет границы видимой области после центрирования. Для каждого спорного маршрута записываем диаграмму, исходный и конечный узлы, сторону, участок и замер. Замер зазора делаем только там, где участки действительно идут рядом. Отдельно проверяем повороты и пересечения по всему контуру. Если после исправления появилось новое пересечение или зазор, его тоже выносим на приёмку.
